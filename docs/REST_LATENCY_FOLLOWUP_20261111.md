# KIS REST가 하루 종일 느렸다 — 2026-11-11

2026-11-11 로그 분석에서 나왔다. 운영 `release/20261111-2`, 지문 746dd0f1cd3a, PAPER.

## 1. 현상

09시부터 15시까지 KIS REST 응답이 평소보다 훨씬 느렸다. 6초 넘게 걸린 호출이 186건이다. 직전 네 거래일은 0 ~ 3건이었다.
진입 주문은 종목 선정 11.9초 뒤에 접수됐고, 청산 주문 API는 3.2초 걸렸다.

## 3. 원인 (확정 안 됨)

KIS 모의 서버(`openapivts`) 쪽인지, 이 PC·회선 쪽인지 가르지 못했다. 봇은 KIS 말고 다른 호스트까지의 왕복 시간을 남기지 않는다.
랜카드·DNS 이벤트가 없고 알림이 첫 시도에 나갔다는 것은 회선이 통째로 끊기지 않았다는 뜻일 뿐이다.

## 4. 영향

- **진입(실측).** 선정 → 주문 접수 11.9초(11/10은 5.8초). 주문이 첫 캡처 체결보다 8.3초 늦게 닿았다(개장 체결은 그보다
  앞이다). 이날은 값이 내려간 뒤라 시가 6,150원보다
  81원 낮은 6,069원에 들어갔다(−91,692원, 추정). 값이 오르는 날이면 반대로 더 비싸게 사거나 지정가에 닿지 않는다
  (진입 티켓 8.20절, 11/05에 주문 API 2.6초로 시가보다 0.8% 위에 진입).
- **청산(실측).** 트레일링 발동(09:01:27.448, 발동가 6,090원, 스탑 6,099원) 뒤 주문 API가 3,202ms 걸렸다. 09:01:28 ~ 30의 체결
  범위는 6,060 ~ 6,100원이었고, 09:01:30에 평균 6,073.71원으로 체결됐다. 발동가보다 16원 낮다(18,112원, 추정). 주문이 바로
  접수됐다면 얼마에 체결됐을지는 알 수 없다.
- **분봉 정정.** 매분 호출이 5 ~ 12초씩 걸렸다. 실패는 1건이고 마지막 정정은 15:26:57에 됐다.
- **시세 수신.** 13:37 단절로 442주를 놓쳤다. 청산 뒤라 손익 영향은 없다.
- 하루 관측이다. 다음 날에도 이어지는지는 아직 모른다.

## 5. 선택지 (결정 전)

- **가. 기록만 한다.** 하루뿐이다. 다음 날들의 `LATENCY_HIGH`를 보고 다시 판단한다.
- **나. 일일 로그 분석에서 매일 센다.** 스킬 4.0절에 "6초 이상 지연 건수"와 "진입 전 네 호출 시간"을 적는 줄을 더한다.
  스킬과 문서만 바뀐다(지문 무관).
- **다. 어느 쪽이 느린지 가르는 측정을 둔다.** 장중에 KIS가 아닌 호스트(또는 KIS 호스트의 TCP 연결 시간만)를 주기적으로 재는
  읽기 전용 스크립트를 따로 돌린다. `scripts/`라 지문과 무관하다. 개발 트리에서 장중에 KIS REST를 부르지 않는 규칙과 부딪히지
  않도록 KIS API 호출은 넣지 않는다.
- **라. 진입 전 REST를 줄이거나 동시에 부른다.** 매수가능·VI·호가 세 호출이 차례로 돌아 지연이 그대로 더해진다(이날 8.7초).
  `src/modules/f3_entry.py`는 지문 대상이다. 같은 지문 카운터(11/11 현재 3건)가 0이 되고, 조건 하나로 센다.
- **마. 청산 주문 경로를 따로 본다.** 주문 API가 느릴 때의 처리(타임아웃, 재시도, 호가 재확인)를 `docs/EXIT_ORDER_RATE_WAIT_FOLLOWUP_20261029.md`와
  함께 검토한다. 지문 대상이다.
