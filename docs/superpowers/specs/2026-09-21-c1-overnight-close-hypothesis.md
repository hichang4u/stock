## 0. 왜 이 축인가

트랙 A는 09:00 갭상승 시가에 진입한다. 국내 종가베팅(종가 매수 → 익일 시초가 매도)은
정확히 그 반대편 — A가 진입할 때 마주치는 매도 물량의 일부가 전날 종가에 산 사람들의
이익 실현이다. H1 문서가 "A의 이익은 09:02~09:22에 끝나는 첫 1분 스캘핑"이라고 정리한
것과 맞물린다. 같은 갭을 A는 슬리피지로 내주고 종가베팅은 먹는다. 그 갭을 먹는 쪽에
설 수 있는지 묻는다.

A와 독립인 트랙으로 둔다. A의 진입 시각을 전날로 당기는 안(A의 지문·실적 리셋 불가피)과
과거 데이터 검증만 하는 안(소급 불가)은 2026-09-21 브레인스토밍에서 기각했다.

## 1. 가설

> 매 거래일 D-0 15:32에 §2 규칙으로 후보를 고르고, **랭크 1 종목을 D-0 종가에 매수**해
> **D+1에 트랙 A의 F4 규칙(하드스탑 −2.0% / 스텝 2.5%·트레일 2.0% / 15:15 타임아웃)으로
> 청산**하면, 비용 차감 후 거래당 기대수익이 0보다 크다.

메커니즘 (한 문장): **마감까지 매수세가 유지된 종목(상승 마감, 고가 근처 종가, 거래대금
급증)은 밤사이 관심이 이어져 익일 시가가 종가 위에 서고, 그 갭과 초반 추세를 A의 청산
규칙이 그대로 회수한다.**

청산을 시초가 전량이 아니라 F4로 둔 이유: A와 같은 자로 재면 두 트랙의 손익이 직접
비교되고, 시초가 전량 변형의 손익은 같은 분봉에서 부 지표로 공짜로 나온다(§4.2).

## 2. 선정 규칙 (등록일에 고정)

실행 시각 **15:32 KST** — 종가 확정 후. A의 F5(15:15)·캡처 최종화(15:20)와 REST 유량이
겹치지 않는다.

### 2.1 유니버스

KIS `ranking/fluctuation` (`paper_fast_probe._ranking_params`와 같은 파라미터, 등락률 범위만
§2.2 값으로) 코스피 `0001`·코스닥 `1001` 각 상위 30 → 최대 60종목.

**정정 (2026-09-21, 첫 dry-run 후).** 이 호출이 쓰는 TR `FHPST01710000`의 응답 필드
(`mksc_shrn_iscd`, `vol_inrt`, `avrg_vol`, `nday_vol_tnrt` …)는 KIS **거래량순위** 출력이고,
`fid_rsfl_rate1/2` 서버 필터는 적용되지 않는다 — 09/21 dry-run에서 유니버스 58행 중 21행만
등락률 [3, 25) 안에 있었다. 따라서 실제 유니버스는 **"시장별 거래량 상위 30"** 이고 등락률
범위는 클라이언트에서 건다(§2.2 첫 조건). 트랙 A의 F1 프로브도 같은 TR을 쓰므로 A와 같은
모집단이다. 등록 전 정정이라 판정에는 영향이 없고, 문서의 "등락률 상위"라는 서술만 사실에
맞게 고친 것이다. 규칙·임계값은 그대로다.

### 2.2 필터 (모두 만족)

| 조건 | 값 | 근거 |
|---|---|---|
| 당일 등락률 `r` | **+3.0% ≤ r < +25.0%** | 상승 마감. 상한가(≈+30%)는 종가 매수가 안 되고, 25% 이상은 익일 갭하락이 비대칭 |
| 종가 위치 | **(종가 − 저가) / (고가 − 저가) ≥ 0.8**; 고가 = 저가면 제외 | 윗꼬리 짧음 = 마감까지 매수세 유지 |
| 거래대금 급증 | **당일 거래대금 ≥ 직전 20거래일 평균 거래대금 × 2.0** | 일봉 `inquire-daily-itemchartprice`(catalyst_label과 같은 TR) 후보당 1콜. 20일치가 없으면(신규 상장) 제외 |
| 유동성 하한 | 당일 거래대금 ≥ 10억원, 종가 ≥ 1,000원 | A의 F1 하한과 정렬 |
| 제외 | 관리종목·거래정지·정리매매·ETF/ETN/스팩 | 랭킹·현재가 응답 플래그. 플래그가 없으면 제외하지 않고 기록에 남긴다 |

세 임계값(3%·0.8·2.0배)과 순위 기준은 자연 경계 또는 문헌의 정석 값이며 데이터에 맞춘
값이 아니다. 표본을 본 뒤 조정하면 H1 §6이 말하는 사후 탐색이다.

### 2.3 순위와 기록

- 순위: **거래대금 배수(당일 / 20일 평균) 내림차순.** 동률이면 등락률 높은 쪽.
- **상위 5개 기록, 랭크 1이 주 표본.** A와 같은 "하루 1종목" 프레임.
- 진입가 = **D-0 종가** — 일봉 `stck_clpr`(있으면), 없으면(일봉 실패 → `DAILY_FAILED`)
  랭킹 응답의 `stck_prpr`로 대체한다(`build_row`, §2.4의 예산 소진·오류 처리와 같다).
  정정(2026-09-21, 전수 리뷰 후): 원문은 스크리닝 시점의 `stck_prpr`가 곧 종가라고
  적었지만, 구현은 처음부터 일봉을 우선하고 `stck_prpr`는 일봉이 없을 때만 쓴다 —
  구현을 바꾼 게 아니라 서술을 코드에 맞춘 것이다.
- 기록 형식: `data/overnight/candidates/<D-0>.jsonl`, 한 줄 = 후보 1개. 필터·순위에 쓴
  원시 필드(등락률, OHLC, 거래대금, 20일 평균, 배수, 플래그)를 그대로 남긴다 — H3처럼
  나중에 다른 규칙으로 재라벨할 수 있게. 필터를 통과하지 못한 유니버스 종목도
  `rejected_reason`과 함께 같은 파일에 남긴다(하루 최대 60행).
- 파일 마지막 줄은 항상 요약 행 `{"summary": true, "date": ..., "universe": N,
  "candidates": K, "degraded": bool}`. 후보 0개인 날도 거부 행과 요약 행은 남는다.
  요약 행이 없는 파일은 중간에 죽은 것이고, 파일이 없는 날은 스크리닝 실패(§3.4)다.

### 2.4 호출 예산

랭킹 2콜 + 거래일 확인 1콜(§3.4) + 필터 1차(이름·등락률 — 랭킹 응답에는 고가·저가가
없어 종가 위치는 일봉이 있어야 안다) 통과 종목의 일봉 1콜씩. 09/21 dry-run 실측 23콜.
최악(60종목 전부 범위 내 + 재시도)을 덮도록 `kis_rest.CallBudget(100)`으로 상한을 건다.
예산이 소진되면 남은 종목은 `DAILY_FAILED`이고 그날은 `degraded`다.

## 3. 데이터 흐름과 구성요소

전부 `scripts/`와 `data/overnight/` 안에서 끝난다. `main.py`·`src/modules`는 건드리지
않는다 — 전략 지문 무관, 운영 프로세스와 상태 결합 없음.

```
D-0 15:32  overnight_screen.py  ──▶ data/overnight/candidates/<D-0>.jsonl
                                     ⎿ KIS ranking ×2, daily-itemchartprice ×N

D+1 15:45  track_b_backfill.py  ──▶ data/backtest_bars/<D+1>_<ticker>.json  (09:00~15:30 분봉)
           (needed_pairs에 overnight 후보 (D+1, ticker)를 합류 — 기존 랭크 1~5 쌍과 같은 경로)

언제든    overnight_sieve.py     ──▶ data/overnight/results/<D-0>.json + 집계 표
                                     ⎿ 진입 = D-0 종가, D+1 분봉에 F4 규칙 재생
```

### 3.2 분봉 재생 규칙

- 봉 안의 고가·저가 순서는 알 수 없으므로 트랙 B와 같이 **"저가 먼저"(보수적)** 로 고정.
  같은 봉에서 스텝 도달과 이탈이 겹치면 이탈.
- **첫 봉 시가가 이미 하드스탑 아래(시가 갭 ≤ −2.0%)면 09:00 시가에 하드스탑.** 갭
  리스크를 그대로 반영한다. 갭이 −2% 안이면 첫 봉부터 보통 규칙.
- 후보가 그날 A의 종목과 같으면 `strategy_ticks`로도 재생해 분봉 재생과의 차이를
  기록한다(§4.2 보정값).
- 비용: 개선 계획 §2 상수(왕복 0.18%p, 하드스탑 슬리피지 0.30%p, 트레일 0.15%p,
  타임아웃 0.20%p). 종가 매수의 진입 슬리피지는 0으로 둔다 — 마감 동시호가 단일가
  체결을 가정. 이 가정은 §6 (a)에서 재검증한다.
- 총손익·비용 차감·슬리피지 차감 세 값을 모두 저장하고 **판정은 슬리피지 차감값**으로.

**정정 (2026-09-21, 첫 리뷰 후 — 표본 무결성 가드 추가).** 규칙: 시가 갭의 절대값이
30%를 넘으면(`|갭| > 30%`) 의심 행(`SUSPECT_CORPORATE_ACTION`)으로 표시해 랭크 1 주
표본 n에서 제외하고, `missing.suspect_corporate_action`으로 따로 센다. 정확히 −30%는
KRX 하한가(상하한 ±30%)라 넘는 것이 아니므로 의심하지 않고 표본에 남긴다(보통
`GAP_HARD_STOP` 등 일반 규칙대로 처리). 사유: 사전등록 후 첫 리뷰에서 액면분할·감자
같은 기준가 변경이 정상 갭하락 손익 분포에 섞이는 것을 막기 위해 추가한 표본
무결성 장치이며, §4.1의 임계값·판정식은 바꾸지 않는다.

### 3.3 스케줄링

`StockBot_Backfill`과 같은 방식으로 Task Scheduler `StockBot_OvernightScreen` 15:32
등록, 운영 트리(`stock-prod`)에서 실행. 결과는 운영 트리 `data/overnight/`에 쌓이고
개발 트리에서 `--root D:\Private\stock-prod`로 읽는다(기존 체 스크립트와 같다).
등록 절차는 `docs/DEV_ENV.md` §11(워치독) 형식으로 같은 문서에 추가한다.

### 3.4 실패 처리

- 스크리닝 실패(토큰·API·예외): 후보 파일을 남기지 않는다. **다음날 재실행 불가**
  (종가 이후 랭킹은 복원 안 됨) → 그날은 표본에서 빠지고 §4.3의 결측으로 센다. 런처
  로그(`data/logs/overnight_screen_<stamp>.log`)에 트레이스백이 남는다.
- **휴장일**: 랭킹은 전 거래일 값을 그대로 돌려주므로, 루프 전에 달력 종목(`005930`)의
  일봉으로 오늘 봉이 있는지 1콜로 확인한다. 없으면 파일을 남기지 않고 정상 종료(0)한다 —
  그날은 결측이 아니라 "거래일 아님"이다. Task Scheduler 트리거도 평일로 제한한다.
  유니버스가 비어도(두 시장 모두 0행) 파일을 남기지 않고 실패로 끝낸다.
- 백필 실패: 기존 재실행으로 채워진다(멱등).
- 랭킹은 왔는데 일봉이 일부 실패: 실패한 종목은 `rejected_reason=DAILY_FAILED`로
  기록하고 나머지로 순위를 낸다. 랭크 1이 그 종목이었을 가능성은 알 수 없으므로 그날
  `degraded=true`를 남기고 §4.3에서 따로 센다.

**정정 (2026-09-21, 전수 리뷰 후 — D+1 오추정 수정).** D-0의 D+1을 "그 다음으로 존재하는
후보/분봉 파일 날짜"로 추정하면, D+1에 후보 파일도 분봉도 전혀 없는 날(기계·API가 오후
내내 죽은 날) D+2가 조용히 D+1로 둔갑해 이틀 보유가 사전 등록 표본에 섞인다. 이를 막기
위해 `data/overnight/calendar.json`(거래일 문자열의 정렬된 목록)을 둔다 — 출처는
`overnight_screen.py`의 휴장일 가드가 이미 부르는 005930 일봉이고, 프로브가 통과한
실행마다(TRADING_DAY·HOLIDAY 둘 다, FAILED는 제외) 기존 파일과 합집합으로 갱신한다.
`track_b_backfill.needed_pairs`와 `overnight_sieve`는 이 달력에서 D+1(달력상 D-0 다음
거래일)을 구한다 — 다음 거래일이 달력에 없으면 그 날은 대기 중으로 건너뛴다. 달력
파일이 아직 없는 초기에는 기존 "파일 존재" 휴리스틱으로 되돌아간다. `overnight_sieve`의
`missing["screen_failed"]`도 이제 이 달력으로 센다: [최초 후보 파일 날짜, 오늘) 구간의
거래일 중 후보 파일이 아예 없는 날. 달력이 없으면 `screen_failed=0`이고
`screen_failed_unknown=true`를 남긴다. 규칙·임계값·판정식은 바꾸지 않는다 — D+1을
추정하는 구현 디테일의 버그 수정이다.

### 3.5 정리한 것 (YAGNI)

Telegram 알림, UI, DB 테이블, 실주문 — 전부 없다. 파일 두 디렉터리로 충분하다. 승격
단계(§6 ②)에서 `trades.track='C'`가 필요해지면 그때 멀티트랙 설계 §4대로 간다.

## 4. 판정 기준 (등록일에 고정)

### 4.1 주 지표와 판정

- **주 지표**: 일별 랭크 1 후보 1건의 슬리피지 차감 손익%. 후보 0개인 날은 표본에서
  제외하고 "거래 없음"으로 따로 센다.
- **표본**: 랭크 1 거래일 **n ≥ 50**, 등록 이후 전향적 표본만.
- **통과**: 다음 셋 모두.
  1. 평균 > 0
  2. paired bootstrap(10,000회) 95% 신뢰구간 하한 > 0
  3. 상위 수익 2건 제거 후 평균 > 0
- **조기 중단**: n = 30 시점에 평균 < −1.0% 또는 누적 최대 낙폭 < −15%p → 축을 닫고
  §7에 기록한다.
- **첫 점검**: 2026-10-31 (H1과 같은 날). 수치는 보되 n = 50 전에는 판정하지 않는다.
- **예상 시점**: 거의 매일 후보가 있으면 2026년 12월 말~2027년 1월 초.

### 4.2 부 지표 (기록만, 판정에 안 씀)

- **시가 갭 분포** (D+1 시가 / D-0 종가 − 1) — "시초가 전량" 변형의 손익이 그대로 나온다.
  트레일 청산과 어느 쪽이 나은지 기록만.
- **랭크 1~5 합산·랭크별 평균** — 순위 기준(거래대금 배수)에 정보가 있는지.
- **청산 사유 분포** (HARD / TRAIL / TIMEOUT, 시가 하드스탑 별도) — A와 형태 비교.
- **틱 vs 분봉 재생 차이** — 후보가 A 종목과 겹친 날. 분봉 재생의 편향 보정값.
- **A와 같은 날 상관** — C가 A와 독립 수익원인지. 승격 시 자본 배분 근거.
- **비용 민감도** — 비용 0.10/0.18/0.25%p, 슬리피지 0.5/1.0/1.5배.

### 4.3 결측 회계

- 스크리닝 실패일, `degraded=true`일, 백필 미완료일을 각각 센다. 실패일이 전체의 20%를
  넘으면 통계보다 수집기를 먼저 고친다.
- 후보 0개인 날의 비율도 기록한다 — 규칙이 너무 좁으면 n = 50까지 예상보다 오래 걸린다.
- `suspect_corporate_action`(|시가 갭| > 30%로 의심돼 랭크 1 주 표본 n에서 빠진 건수,
  §3.2 정정)도 센다 — 기업 행위 빈도가 이상히 높으면 임계값이 아니라 데이터원을
  의심한다.
