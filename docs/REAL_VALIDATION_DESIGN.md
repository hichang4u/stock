# 실전 전환의 수익성·실행 경로·위험 통제 설계

작성일: 2026-11-11

상태: **설계 반영 완료, 구현·운영 검증 미완료**. 이 문서의 새 게이트·필드는 구현 요구사항이며
현재 코드의 기능이나 승인 결과가 아니다. 기존 가설 H1~H4/C1의 임계값은 변경하지 않는다.

## 1. 목적과 적용 범위

목표는 무손실 보장이 아니라, 계좌 손실 예산 안에서 비용 반영 기대수익이 양수인지
미래 데이터로 검증하는 것이다. 당일 청산은 익일 노출을 줄이지만, 급락·VI·거래정지·
주문 지연 때문에 손실 상한이나 당일 전량 청산을 보장하지 않는다.

이 설계는 주문을 실행하는 트랙 A의 상주 REAL 신규 진입에 적용한다. 다른 트랙의 성과로
A의 자격을 채우지 않는다. 기존 PAPER 개선 계획의 상대 성능 검정도 유지한다.
기준 전략보다 덜 잃는 것과 전략 자체의 순기대값이 양수인 것은 별개다.

| 우선순위 | 필수 결과 | 현재 공백 |
|---|---|---|
| P1 수익성 게이트 | 운영 안전성·절대 수익성 모두 통과해야 REAL 신규 진입 허용 | 정상 청산 20회에 수익성 조건 없음 |
| P2 실행 경로 일치 | 검증한 경로·정책으로 REAL 실행, 환경 차이의 영향 별도 검증 | 빠른 경로는 PAPER 전용 |
| P3 체결·계좌 위험 | 실측 비용·체결 가능성과 계좌 손실 예산으로 수량·진입 통제 | 연구 상수·투입비율만으로 충분하지 않음 |

## 2. P1 — 운영 안전성과 절대 수익성 분리

### 2.1 신규 진입 자격

최종 조건은 다음 AND 결합이다. 가중 점수로 다른 항목의 실패를 상쇄하지 않는다.

`eligible_for_real = operational_ready AND profitability_passed AND execution_parity_passed
AND risk_policy_valid AND evidence_current AND NOT risk_halted`

- `operational_ready`: 기존 정상 청산 20회·안전 설정·스모크·알림·운영자 훈련 조건.
- `profitability_passed`: 아래 잠금 미래 검증의 절대 순수익 조건.
- `execution_parity_passed`: §3의 동일 경로·환경 차이 검증.
- `risk_policy_valid`: §4의 필수 한도 설정과 주문 직전 위험 예산 확인.
- `evidence_current`: 전략·경로·비용·위험 정책·검증 규칙의 승인 증거가 현재 버전과 일치.
- `risk_halted`: 손실 한도 초과·미확인 주문 등 지속성 있는 신규 진입 중단 상태.

판정값은 `NOT_EVALUATED / COLLECTING / INSUFFICIENT / FAIL / PASS`로 구분한다.
미평가·표본 부족·조회 실패·증거 만료는 통과가 아니다. 기동과 매수 전 양쪽에서 검사한다.
게이트 실패는 보호 청산·취소·주문 대사를 차단하지 않는다. 점검용 REAL 1주 스모크는
기존 명시적 수동 절차로만 허용하고 상주 매수 자격이나 수익성 표본으로 사용하지 않는다.

### 2.2 잠금 미래 검증

전략 선택·탐색에 쓰지 않은 미래 구간을 새로 지정한다. 아래 설계값과 위험 정책을
`experiment_registry`에 잠근 뒤 수집하며, 결과를 본 뒤 완화하지 않는다.

- 최소 **60개 실제 거래 발생일**. 이는 수집 하한이지 충분성이나 수익 보장이 아니다.
  무거래일도 사유와 함께 달력에 남기고 계좌 일별 수익률 계산에는 포함한다.
- 판정일은 시작 전에 날짜로 고정한다. 그날 60일 미만이면 `INSUFFICIENT`다.
  매일 유리한 신뢰구간이 나올 때까지 반복 판정하지 않는다.
  연장·재시험은 새 판정일과 반복 검정 처리 방식을 사전등록한다.
- 수수료·세금과 실행 가능한 체결 모델을 반영한 거래당 평균 순손익률의
  거래일 블록 bootstrap 95% 신뢰구간 하한이 **0 초과**여야 한다.
  블록 길이·재표집 횟수·난수 시드·복수 시험 보정 방식도 시작 전에 고정한다.
- 계획한 투입금·수량을 반영한 계좌 기준 순누적손익이 양수여야 한다.
  전략 투입금 수익률과 계좌 수익률을 별도 표시한다.
- 수익 상위 1건·2건 제거 후에도 평균 순손익률이 양수여야 한다.
- 기본 비용 및 불리한 비용·지연 시나리오에서 평균 순손익률이 양수이고,
  계좌 MDD·CVaR·연속손실이 사전등록 한도 이내여야 한다.
- 시장 상승·하락·변동성 구간별 표본 수와 결과를 보고한다. 승인 대상으로 정한
  구간의 표본 요건이 미달이면 그 구간의 운용 자격을 부여하지 않는다.

실제 거래 결과와 전일/전체 후보 경로 결측을 구분한다. 경로가 불완전해도 실제 발생한
손실·수수료·미해결 포지션은 계좌 위험 통계에서 삭제하지 않는다. 수동 청산·실패 거래는
원인별로 공개하고 전체 계좌 집계에 포함한다. 과거 혼합 지문 성과는 참고용으로 유지한다.

## 3. P2 — PAPER·REAL 실행 경로 계약

코드 동결과 새 표본 수집 전에 다음 중 한 경로를 확정한다.

1. 기존 경로: PAPER 빠른 경로를 끄고 REAL과 같은 진입 정책으로 새 표본을 수집한다.
2. 빠른 경로: REAL 지원을 별도 전략 변경으로 구현·검증한 뒤 새 표본을 수집한다.

선택되지 않은 경로의 성과는 새 경로의 승인 표본에 합산하지 않는다. 경로 변경은
전략 변경이며 기존 20회 카운트·수익성 증거를 재사용하지 않는다.

### 3.1 저장할 실행 계약

`execution_profile_id`와 해시에는 다음을 포함한다.

- 후보 정보의 기준 시각, 선정·락업·재검증 순서, 개장/첫 체결 대기 정책
- 지정가 상한, 호가 신선도, VI 처리, 진입 마감
- 주문 수량·현금 예산, 미체결 취소·부분체결·응답 유실 대사 정책
- 호출 우선순위·재시도·타임아웃과 모드별 호출 한도

공통 판단 로직을 공유하고 모드별 어댑터는 인증·TR·서버 제한 차이를 담당한다.
호출 간격이나 체결 서버의 차이를 없다고 가정하지 않는다. 동일 입력 재생 시 후보·
진입 허용 여부·주문 상한·수량의 일치를 확인하고, 환경 차이는 별도 실측한다.

### 3.2 완료 증거

- 동일 시각 입력의 PAPER/REAL 어댑터 재생에서 판단·주문 의도가 일치한다.
- 실제 서버의 읽기 전용 점검과 수동 최소수량 스모크로 TR·호가·취소·체결을 대사한다.
- 선정→전송→접수→체결의 구간별 p50/p95/max와 표본 수를 모드별로 남긴다.
- 주문 규모별 체결 모델에 REAL 관측 지연을 적용해도 §2 수익·위험 조건을 만족한다.
  표본 부족이나 PAPER와의 차이 미해명은 `execution_parity_passed=false`다.
- 환경 차이 허용 범위·필요 표본 수·재검증 주기를 관측 수집 전에 계약에 등록한다.

## 4. P3 — 체결 현실성과 계좌 손실 예산

### 4.1 비용·체결 데이터

연구 비용 0.18%p와 사유별 슬리피지 상수는 시나리오 가정으로 보존한다.
실계좌 요율이나 실측 비용으로 표기하지 않는다. 비용 정책은 적용일·시장·계좌 수수료
조건별로 버전 관리하고 체결 내역·증권사 정산과 대사한다.

- 주문 판단가, 당시 매수/매도 호가와 잔량, 거래소/수신 시각, 주문 수량·금액
- 전송·접수·각 부분체결 시각, 체결 수량·가중평균가, 취소·미체결 잔량
- 수수료·세금·총손익·실제 순손익, 결정가 대비 슬리피지
- 데이터 출처·완전성, 비용/체결 모델 버전, 추정값과 정산값 구분

실제 체결가로 계산한 손익에는 이미 가격 미끄러짐이 포함된다. 실제 순손익에서 이를
다시 차감하지 않는다. 별도 보수 스트레스 손익은 추가 불리 조정임을 표시한다.
가상 거래는 주문 수량을 소화할 수 있는 호가·시간 경로로 계산한다. 최우선 호가 하나나
분봉 고저가만으로 전량 체결을 가정하지 않는다. 잔량/순서가 없으면 체결 미확인으로 남긴다.

### 4.2 위험 정책과 주문 예산

구현 전에 다음 정책값·단위·기준 자본·산출 창·복구 조건을 확정해야 한다.
사용자의 실제 자본·허용 손실을 알 수 없으므로 숫자는 임의로 확정하지 않는다.
필수값 미정·0으로 무제한·오래된 계좌 자료는 REAL 신규 진입 차단 사유다.

| 필수 정책 | 의미 |
|---|---|
| 거래당 손실 예산 | 승인 계좌 자본 대비 원/비율, 기존 노출·미체결 주문 포함 |
| 일일 손실 한도 | 실현+평가손익·비용 포함, 당일 신규 진입 중단선 |
| 계좌 최대 낙폭 | 입출금 보정 자산 고점 대비, 보유 중 평가손실 포함 |
| CVaR·연속손실 한도 | 계산 창·최소 표본·한도, 표본 부족 시 처리 |
| 절대 주문 상한·투입비율 | 기존 20% 이하 조건도 유지, 두 한도 중 작은 값 |
| 유동성·지연 제한 | 사용 가능한 호가 깊이·참여율·최대 시세 나이·진입 지연 |
| 스트레스 손실률 | 손절 폭에 지연·갭·불리한 체결·비용을 포함한 수량 산정 가정 |

허용 신규 주문금액은 **현금 한도, 절대 주문 상한, 유동성 한도,
남은 거래당 손실 예산 ÷ 스트레스 손실률** 중 최솟값으로 정하고 호가단위·수량을 내림한다.
손실 예산 산정에 포함한 미체결 매수를 예약해 중복 집행을 막고, 취소·체결 대사 후 해제한다.
하드스탑 -2%만을 최대 손실률로 사용하지 않는다. 스트레스 가정도 실제 손실 상한의 보장은 아니다.

### 4.3 중단·재시작

한도 초과나 주문 상태 불명확 시 `risk_halted`와 사유·시각·정책 버전을 영속화해
재시작으로 풀리지 않게 한다. 일일 중단만 승인된 거래일 전환 절차로 해제할 수 있고,
낙폭·Critical 중단은 대사·원인 조사와 기록된 재개 결정이 필요하다.

중단 시 신규 매수·추가매수는 막되 기존 F4/F5 보호 청산과 취소·대사는 계속한다.
일일 손실선 위반만으로 미확인 매도를 재전송하지 않는다. 청산 불능은 CRIT·수동 대응으로
남기며 CLOSED나 손실 제한 성공으로 표시하지 않는다. 기존 실험 중단 규칙은 별도로 유지한다.

## 5. 증거와 검증 계약

승인 증거는 `strategy_fingerprint`, `experiment_id`, `execution_profile_id`,
비용·체결·위험 정책 해시, 데이터 해시, 평가 규칙 버전, 평가일·만료일, 결과·차단 사유를
참조한다. 저장 위치·스키마는 DB 구현 설계에서 확정한다. 과거 결과를 덮어쓰지 않는다.
판단에 영향을 주는 버전 변경·증거 만료·한도 위반 때 자격을 다시 평가한다.
안전성 수정도 현행 지문 규칙에 따라 새 표본으로 시작하고, 릴리스당 조건 하나 원칙을 지킨다.

| 검증 영역 | 필수 시나리오·기대 결과 |
|---|---|
| 수익성 | 정상 청산 20회 전부 손실 → 차단; 표본 부족·미래정보 누출·낡은 증거 → 차단 |
| 통계 | 탐색/미래 구간 분리, 고정 판정일 재현, 비용 중복 차감 방지, 실패 거래 포함 |
| 경로 | 모드별 동일 입력의 주문 의도 일치, 경로 변경 시 기존 승인 무효 |
| 수량 | 비용·지연·유동성 악화 시 예산 내 축소/거래 포기, 미체결 예약 중복 방지 |
| 위험 | 평가손실·입출금·재시작·한도 경계, 중단 후 매수 차단 및 보호 청산 허용 |
| 운영 | 지연·단절·부분체결·응답 유실·청산 불능에서 대사·CRIT·수동 대응 확인 |

mock 테스트 통과만으로 운영 검증을 완료 처리하지 않는다. 읽기 전용 점검→PAPER 운영→
명시적 최소수량 스모크 순으로 증거를 남긴다. 본 설계는 실제 주문의 실행 승인이 아니다.

## 6. 구현 전 결정과 작업 순서

1. 기존/빠른 실행 경로를 선택하고 실행 계약·변경 범위를 확정한다.
2. 계좌 위험 정책의 필수값, 비용·체결 모델과 실측 계획을 확정한다.
3. 미래 검증 시작일·판정일·통계 세부값·시장 구간 요건을 사전등록한다.
4. 수익성·경로·위험 증거와 게이트를 구현한다. 전략 동작 변경은 릴리스별로 분리한다.
5. 회귀·재생·장애 검증 후 REAL 호환 설정을 PAPER에 적용하고 새 지문을 동결한다.
6. 운영 안전성 표본과 잠금 미래 표본을 수집한다. 어느 하나 부족하면 REAL은 차단한다.
7. 모든 조건을 충족한 뒤에만 실전 전환 점검표의 최종 운영 승인을 진행한다.

현재 완료: 이 설계의 문서화. **1~7의 결정·구현·검증·전환은 미완료**이며,
문서 추가만으로 현재 `eligible_for_real` 코드가 강화되지는 않는다.
