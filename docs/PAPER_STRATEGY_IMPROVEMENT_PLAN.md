# PAPER 전략 개선 운영 계획

## 결론

이 프로젝트의 다음 단계는 매일 로그에서 발견한 현상에 맞춰 전략값을 바로 수정하는
것이 아니다. 설정을 일정 기간 고정하고, 선택되지 않은 후보까지 포함한 결과 데이터를
축적한 뒤, 사전에 정한 통계 기준을 통과한 변경만 PAPER에 승격한다.

개선 사이클은 다음 순서를 반복한다.

> 수집 → 데이터 품질 확인 → 가설 등록 → shadow 비교 → 잠금 검증 → PAPER 승격/폐기

한 사이클에서는 원칙적으로 선택, 진입, 청산 중 한 영역만 변경한다. 주문 안전성 결함은
언제든 수정할 수 있지만, 안전성 수정과 전략 성능 변경은 같은 실험으로 평가하지 않는다.

단, 이번 0단계의 F1 최소 갭 2.5%와 F4 트레일 폭 2.0%는 신규 기준선을 열기 전
초기 설정 정렬로 일괄 적용했다. 이 초기 묶음은 개선 사이클 1회로 평가하지 않으며,
기준선 수집이 시작된 뒤부터 위의 한 사이클 한 영역 원칙을 적용한다.

**0단계 정렬 묶음과 롤백 규칙 (2026-09-14 결정).** 위 묶음은 사이클을 거쳐 승격된
설정이 아니므로 §6의 "승격 후 롤백 규칙"을 적용하지 않는다. `trailing_shadow_comparisons`의
1.5% 대 2.0% 비교는 롤백 감시가 아니라 단계 B의 확증 수집으로 취급하며, 판정은 아래
사전등록식으로만 한다.

> discordant pair 20건 도달 시, 1.5% 대비 2.0%의 paired 평균 손익 차이 < 0 이고
> paired bootstrap 95% 상한 < 0 이며 상위 수익 2건 제거 후에도 방향이 유지되면,
> `STEP_TRAIL`을 0.015로 복귀하는 변경을 단계 C 잠금 검증(최소 10거래일·discordant
> pair 5건)에 올린다. 잠금 검증에서도 방향이 유지될 때만 다음 릴리스에 반영한다.
> 하나라도 실패하면 2.0%를 유지하고 새 실험으로 되돌린다.

결정 시점 기준 표본은 16건(discordant 7건, 전부 1.5% 우세, 누적 paired 차이 −3.83%p)이다.
이 숫자는 판정식의 근거가 아니라 기록이며, 20건 도달 전에는 어떤 값도 변경 사유가 되지
않는다. §6 "실험 중단 규칙"과 §4의 `data_complete=0` 제외 규칙은 그대로 적용한다.

## 1. 목표와 판정 기준

### 목표

1. 오를 가능성이 상대적으로 높은 종목을 상위에 배치한다.
2. 개장 지연과 추격 매수로 발생하는 진입 손실을 줄인다.
3. 틀린 선택의 손실을 제한하면서 상승한 거래의 이익을 안전하게 확보한다.
4. 수수료·세금·슬리피지를 반영한 순기대값을 높인다.

“오를 종목을 정확히 맞힌다”는 절대 목표로 사용하지 않는다. 통계적으로 검증할 수 있는
목표는 후보군 대비 선택 우위, 비용 반영 기대손익, 손실 꼬리와 최대 낙폭의 개선이다.

### 최적 설정의 정의

과거 표본에서 평균손익이 가장 높았던 단일 값이 아니라 다음 조건을 만족하는 구간을
최적으로 본다.

1. 최악 10% 평균손실과 최대 낙폭이 허용 범위 안이다.
2. 현재 설정 대비 비용 반영 paired 손익 차이가 양수다.
3. 특정 하루나 소수의 큰 수익을 제외해도 방향이 유지된다.
4. 인접한 설정값에서도 성과가 급변하지 않는다.
5. 잠금한 미래 구간에서도 개선 방향이 유지된다.

## 2. 과거 참고 통계와 신규 기준선

2026-08-12까지의 25건은 현재 설정의 기준선이 아니라 여러 코드·설정 버전이 섞인 과거
참고 통계다.

| 항목 | 과거 참고 값 |
|---|---:|
| 종료 거래 | 25거래일 / 25건 |
| 전략 지문 NULL | 21건 |
| 지문 `58a5a3ba697e` | 1건 |
| 지문 `20e1be68b17c` | 2건 |
| 지문 `4e34b3d9b787` | 1건 |
| 수익 거래 | 11건 |
| 승률 | 44.0% |
| 거래당 평균 총손익률 | +0.296% |
| 중앙값 총손익률 | -1.72% |
| 평균 총손익률 단순 bootstrap 95% 구간 | -0.876% ~ +1.604% |
| F1 원본 스냅샷 | 20파일 / 고유 17거래일 / 원시 908행 |

`pnl_pct`는 `(exit_price / entry_price - 1) × 100`인 수수료·세금 차감 전 총손익이다.
따라서 +0.296%를 비용 반영 성과로 해석하지 않는다. 아래 초기 연구 비용 0.18%p만
기계적으로 차감해도 평균은 약 +0.116%이며, 슬리피지까지 넣으면 0과 구별하기 어렵다.

F1 분석은 파일 수나 원시 행 수를 표본 수로 사용하지 않는다.
`KIS_HISTORICAL_POC.md`의 규칙에 따라 날짜별 09:00:00~09:10:59 KST의 최초 **정상**
스냅샷 하나만 대표로 사용한다. 같은 날 중복, 비정상 소행 스냅샷, 범위 밖 시각을 제외한
뒤 대표 행 수와 품질 통계를 다시 산출한다. 같은 날 후보들은 시장 상황을 공유하므로
후보 분석은 거래일 cluster bootstrap을 사용한다.

“정상” 판정은 완료 이벤트 존재, JSON·필수 필드 무결성, 중복 종목 없음, 최소 universe
coverage를 포함한 코드 규칙으로 먼저 고정하고 `selector_version`을 저장한다. 이 규칙을
정하기 전에는 17거래일 중 실제 분석 가능 거래일 수를 확정하지 않는다.

### 신규 기준선 정의

현재 설정의 통계 기준선은 다음 조건을 모두 만족한 첫 PAPER 거래일부터 새로 시작한다.

1. `experiment_registry`에 기준 실험이 등록되어 있다.
2. 비용·슬리피지 가정과 비교할 주 가설이 잠겨 있다.
3. 실행 거래에 현재 `strategy_fingerprint`와 `experiment_id`가 모두 저장된다.
4. 후보·가격 경로 필수 데이터 수집이 성공한다.

지문이 NULL이거나 다른 과거 거래는 설명 통계에는 포함할 수 있지만 paired 승격 검정에는
섞지 않는다. 전략 파일이나 성능 설정이 바뀌면 새 지문·새 실험 ID로 기준선을 다시 연다.

### 현재 PAPER 전략값

| 설정 | 값 |
|---|---:|
| F1 최소 갭 | 2.5% |
| F1 선호 구간 상단 | 8.0% |
| F1 과열 제외 상단 | 10.0% |
| 첫 트레일 스텝 | +2.5% |
| 현재 트레일 폭 | 2.0% |
| 비교 기준 트레일 폭 | 1.5% |
| 하드스탑 | -2.0% |
| 강제 트레일 활성화 | 15:05 |
| F5 타임아웃 청산 | 15:15 |
| KIS 호출 동시성 | 1 |
| KIS 호출 간격 | 1.1초 |

강제 트레일 15:05, F5 타임아웃 15:15, 동시성 1과 1.1초 호출 간격은 초기 청산
실험에서 고정한다. 이 값을 바꾸면 별도 실험으로 등록하고 시험 횟수에 포함한다.

### 초기 PAPER 비용·체결 가정

PAPER 체결은 REAL의 급락 슬리피지를 재현한다고 가정하지 않는다. 초기 연구 상수는 실제
요율의 단정이 아니라 보수적인 비교 가정이며, 실험 등록부와 `strategy_configs`에 함께
저장한다.

| 상수 | 초기값 | 적용 |
|---|---:|---|
| `BASE_ROUND_TRIP_COST_PCT` | 0.18%p | 매수·매도 수수료·세금 총합 연구 가정 |
| `ENTRY_SLIPPAGE_FALLBACK_PCT` | 0.10%p | 실행 가능한 매도호가가 없을 때 매수 불리 조정 |
| `HARD_STOP_SLIPPAGE_PCT` | 0.30%p | 하드스탑 가상 매도 불리 조정 |
| `TRAILING_SLIPPAGE_PCT` | 0.15%p | 트레일 가상 매도 불리 조정 |
| `TIMEOUT_SLIPPAGE_PCT` | 0.20%p | F5 가상 매도 불리 조정 |

- 확인 가능한 실제 호가·체결 편차가 있으면 관측값과 가정값 중 더 불리한 값을 사용한다.
- 총손익, 비용 차감 손익, 슬리피지까지 차감한 보수 손익을 각각 저장한다.
- 비용은 0.10/0.18/0.25%p, 슬리피지는 기본 가정의 0.5/1.0/1.5배 민감도를 함께 보고한다.
- 상수 변경은 기존 결과를 덮어쓰지 않고 새 `config_id`로 전체 재생한다.
- 이 비용 모델을 코드·DB 설정으로 고정하고 단위 테스트하기 전에는 승격 통계를 만들지
  않는다.

## 3. 매일 생성할 네 가지 보고

### 3-1. 종목 선택 보고

답해야 할 질문은 “선택 종목이 올랐는가”가 아니라 “당시 살 수 있었던 후보 중 좋은
선택이었는가”이다.

필수 항목:

- F1 통과·탈락 후보와 탈락 사유
- 후보별 원본 특징, 점수 구성요소, 최종 점수와 순위
- 선택 종목의 후보군 내 1·3·5·10·30분 수익률 순위
- 선택 종목과 후보 평균·최상위 후보 간 수익률 차이
- `+첫 스텝`과 `-하드스탑` 중 먼저 도달한 장벽과 시각
- 점수 상위 1·3종목의 장벽 성공률과 비용 반영 가상손익

핵심 지표:

- `precision@1`: 선택 종목이 목표 장벽에 먼저 도달한 비율
- `precision@3`: 상위 3개 중 목표 장벽 성공 종목 비율
- 선택 종목의 후보군 내 성과 백분위
- 선택 regret: 같은 날 최선의 실행 가능 후보 대비 손익 차이
- 점수 구간별 성공률: 높은 점수가 실제 성공 확률과 일치하는지 확인

### 3-2. 매수 지점 보고

필수 항목:

- 시가와 시각
- F1 완료, F3 시작, 재검증, 최종 호가, 주문 전송, 체결 시각
- 각 시점의 매도 1호가·잔량과 관측 데이터 나이
- 재검증가→최종 호가→실제 체결가 변화
- 시가·결정가·실제 체결가 기준 각각의 가상 최종손익
- API 대기, 네트워크, 로컬 처리시간별 지연 기여도

가상 체결가는 현재가나 저가가 아니라 해당 시점 매도호가와 주문수량을 소화할 수 있는
호가 잔량을 사용한다. 호가가 없으면 “체결 가능성 미확인”으로 표시하고 수익으로 세지
않는다.

핵심 지표:

- 결정가 대비 매수 슬리피지
- 시가 대비 추격 비율
- 지연 기회비용
- 주문 전 호가 이동률
- 체결 후 30초·1분 MAE

### 3-3. 청산 전략 보고

동일한 실제 가격 경로에 여러 설정을 병렬 적용하되 주문은 현재 PAPER 설정 하나만
실행한다. 확증용 주 가설은 **나머지 값을 고정한 트레일 폭 1.5% 대 2.0% 한 쌍**이다.

다음 27개 격자는 가설 발견을 위한 탐색용으로만 사용하며 이 결과만으로 승격하지 않는다.

- 하드스탑: 1.5%, 2.0%, 2.5%
- 첫 스텝: 1.5%, 2.0%, 2.5%
- 트레일 폭: 1.0%, 1.5%, 2.0%

각 조합에 다음을 기록한다.

- 가상 트리거 시각·가격과 청산 사유
- 보수적 슬리피지 적용 가상 체결가
- 비용 반영 순손익률·순손익금
- MFE·MAE와 고점 이익 확보율
- 현재 설정 대비 paired 손익 차이
- 하드스탑·트레일·타임아웃 비율
- 기준과 결과가 실제로 갈린 discordant pair 여부

이미 구현된 `trailing_shadow_comparisons`는 기존 1.5%와 현재 2.0% 트레일의 첫 비교
단계다. 전체 조합 비교는 범용 `strategy_shadow_results`로 확장한다.

실제 PAPER 체결가가 기준선에 거의 정확히 붙는 현상은 낮은 REAL 슬리피지의 증거가
아니다. 모든 조합 보고에는 위의 사전등록 비용·슬리피지 가정과 민감도 결과를 함께 싣는다.

### 3-4. 안정성·위험 보고

필수 항목:

- 누적 비용 반영 손익
- 최근 5·10·20·전체 거래 평균과 중앙값
- 승률, payoff ratio, 기대손익
- 최대 낙폭과 현재·최대 연속손실
- 최악 10% 평균손실(CVaR 10%)
- 수익 상위 1·2건을 제외한 민감도
- 갭·유동성·시장 상승/하락 등 구간별 결과
- 데이터 누락률과 비교 가능한 거래 수

일일 판정은 다음 셋 중 하나만 사용한다.

- `NO_CHANGE`: 증거 부족 또는 데이터 품질 미달
- `WATCH`: 개선 신호는 있으나 승격 표본 미달
- `PROMOTION_CANDIDATE`: 사전 승격 기준을 충족

## 4. 축적할 데이터 구조

### 4-0. 저장 원칙과 현재 상태

통계 계산에 직접 사용하는 정형 데이터와 실험 결정 이력은 SQLite에 저장한다. JSONL
이벤트 로그는 장애 조사와 원본 감사용으로 유지하지만 통계의 단일 원천으로 사용하지
않는다.

현재 DB에는 실제 선택·주문·체결을 저장하는 `trades`, `orders` 등이 있고,
`trailing_shadow_comparisons`는 코드와 마이그레이션이 추가된 상태다. 실제 DB 파일의
테이블 생성은 변경된 프로그램이 다음에 `db.init()`을 실행할 때 적용된다. 아래 나머지
테이블은 단계별 구현 대상이며 아직 운영 DB에 존재하지 않는다.

| 저장 대상 | 저장 위치 | 기본 키/중복 방지 | 목적 |
|---|---|---|---|
| 실험 정의 | `experiment_registry` | `experiment_id` | 사후 가설 변경 방지 |
| 실험 설정 조합 | `strategy_configs` | `config_id`, 설정 JSON 해시 | 시험 횟수와 파라미터 고정 |
| F1 당시 후보 | `candidate_observations` | 거래일·종목·실험·스냅샷 시각 UNIQUE | 당시 알 수 있었던 정보 보존 |
| 후보 사후 성과 | `candidate_outcomes` | 후보 관측 ID·평가구간 UNIQUE | 선택 정확도와 놓친 후보 분석 |
| 진입 반사실 | `entry_counterfactuals` | 거래 ID·진입 시나리오 UNIQUE | 지연·추격·슬리피지 분리 |
| 청산 반사실 | `strategy_shadow_results` | 거래 ID·설정 ID UNIQUE | 동일 경로에서 설정별 손익 비교 |
| 1.5%/2.0% 비교 | `trailing_shadow_comparisons` | 거래 ID PK | 현재 초기 shadow 비교 |
| 일일 판정 | `daily_strategy_reports` | 거래일·실험 ID UNIQUE | 보고 결과와 변경 결정 감사 |
| 가격 경로 파일 목록 | `price_path_manifests` | 거래일·종목 UNIQUE | 원시 경로 무결성·재생 위치 관리 |

원시 틱을 매 건 SQLite에 동기 INSERT하면 공유 DB 쓰기와 주문 경로가 경쟁할 수 있다.
따라서 선택 종목의 재생 가능한 가격 경로는 다음과 같이 분리한다.

- 파일: `data/strategy_ticks/YYYYMMDD/{ticker}.jsonl.gz`
- 필수 필드: 순번, 거래소 시각, 수신 시각, 가격, 수량, WS/REST 출처, 유효성 판정
- DB manifest: 파일 경로, SHA-256, 행 수, 시작·종료 시각, 누락 구간, 생성 버전
- 기록 방식: 메모리 버퍼 또는 별도 저우선순위 writer 사용
- 주문 판단: 파일 쓰기 성공 여부와 무관하게 현재 F4 로직으로 계속 진행

새로운 설정을 나중에 다시 시험할 수 있으려면 heartbeat 30초 가격만으로는 부족하다.
트레일이나 하드스탑이 어느 쪽에 먼저 도달했는지 재현할 수 있도록 허용된 틱의 시간
순서를 보존해야 한다. 파일 기록 실패는 `data_complete=0`으로 표시하고 해당 거래를
정밀 shadow 통계에서 제외한다.

### 실제 청산 후 가격 경로 요구사항

느슨한 하드스탑과 넓은 트레일을 평가하려면 실제 설정이 먼저 청산된 뒤의 경로가 반드시
필요하다. 선택·체결된 한 종목은 실제 청산 여부와 관계없이 진입부터 고정 F5 시각
15:15까지 가격 경로를 계속 기록한다.

- CLOSED 이후에는 가격 기록만 하고 스탑 계산·주문은 실행하지 않는다.
- 수동 `/api/tracking/stop`, 프로세스 종료, WS 단절로 15:15 이전에 끝나면 manifest를
  `data_complete=0`으로 표시한다.
- post-close WS 재연결을 지원하고, 09:35 이후 저우선순위 REST 백업으로 누락 구간을
  표시·보강한다. REST 표본은 틱의 완전한 대체로 간주하지 않는다.
- F5 직전 주문을 보호하기 위해 백업 조회는 15:14에 중단하고 F5 요청이 항상 우선한다.
- 실제 청산 이후 경로가 불완전한 거래는 더 느슨한 설정의 paired 비교에서 제외한다.
  결측 비율을 설정별로 함께 보고해 타이트한 설정 쪽으로 생기는 선택 편향을 드러낸다.

현재 `F4_POST_CLOSE_OBSERVE_UNTIL`과 WS-only 관측만으로는 이 완전성을 보장하지 못한다.
15:15까지의 durable tick writer와 누락 판정이 0단계 선행 구현이다.

### 후보 사후 가격의 수집 출처와 호출 예산

저장된 F1 스냅샷에는 미래 가격이 없고 기존 PoC가 검증한 과거 조회는 일봉이다. 따라서
후보의 1·3·5·10·30분 수익률을 만들기 전에 KIS 분봉 API의 다음 항목을 조회 전용 PoC로
검증한다.

- PAPER에서 당일 09:00 이후 분봉을 장중 재조회할 수 있는가
- 한 요청의 제공 구간, 페이지 처리, 수정주가·거래소 시각 필드
- 09:00~09:30 MFE·MAE 재현성과 빈 봉·VI 처리
- 1분 봉 안에서 상·하 장벽이 모두 닿은 `AMBIGUOUS` 비율

분봉은 같은 1분 안의 장벽 도달 순서를 알 수 없다. 고가가 상승 장벽 이상이고 저가가
하락 장벽 이하인 봉은 추정하지 않고 `barrier_order=AMBIGUOUS`로 저장한다. 단계 A에서
이 비율을 먼저 산출하며, 높으면 후보 장벽 성공률을 승격 지표로 사용하지 않는다.

모든 후보를 개장 직후 실시간 REST 폴링하는 방식은 금지한다. 동일한 1.1초 직렬 큐를
공유해 주문 경로를 방해하기 때문이다. 초기 수집 계약은 다음과 같다.

- 시작 시각: 09:35 이후
- 우선순위: 저우선순위 조회, 주문·체결·잔고·F5보다 항상 낮음
- 일일 추가 호출 예산: 최대 60회, 재시도 포함
- 대상: 날짜별 최초 정상 F1 스냅샷의 후보, 중복 종목 제거
- 예산 초과·API 미지원: 실시간 폴링으로 대체하지 않고 `missing_reason` 기록

60회가 약 45개 후보의 30분 구간을 안정적으로 수집하기에 충분한지는 PoC에서 확정한다.
부족하면 호출 간격이나 동시성을 바꾸지 않고 대상 정의 또는 수집일을 조정한다.

DB 공통 시각은 `2026-08-12T09:01:17.405031+09:00`처럼 오프셋을 포함한 ISO8601로
저장한다. 거래일은 별도 `YYYYMMDD` KST 필드로 두며, 타임존 없는 시각은 신규 데이터로
허용하지 않는다. 공통 필드는 다음을 포함한다.

- `created_at`, `updated_at`, `source_ts`, `received_at`
- `experiment_id`, `strategy_fingerprint`, `config_id`
- `data_complete`, `missing_reason`, `source`
- 가격 단위, 수익률 단위와 비용 반영 여부
- 원본 스냅샷 또는 가격 경로의 해시

모든 쓰기는 idempotent UPSERT 또는 UNIQUE 제약으로 재시작 중복을 막는다. 후보와 결과를
삭제·덮어쓰기보다 새 실험 ID로 추가하고, 정정이 필요하면 정정 사유를 남긴다.

### 가격 경로 용량과 보존

- 전 틱 저장은 실제 선택·체결된 하루 한 종목으로 제한한다.
- 전체 후보는 검증된 분봉과 요약 결과만 저장하며 후보 전 종목 틱 수집은 금지한다.
- 틱 파일은 시간 단위 gzip chunk로 회전하고 manifest가 모든 chunk를 나열한다.
- 초기 소프트 한도는 압축 후 일 100MB다. 초과 시 기록을 버리지 않고 경고와 실제 용량을
  남기며 단계 A 종료 시 한도를 재산정한다.
- 로컬 원시 틱은 최소 180일 보존하고, 삭제 전 외부 보관 또는 재현 불가 승인 기록이
  필요하다. DB 요약·manifest·해시는 영구 보존한다.

### 후보 관측 `candidate_observations`

선택 당시 알 수 있었던 값만 저장한다.

- 거래일, 종목, 시장, 관측 시각
- 예상가, 전일 종가, 갭, 예상체결량·대금
- 5일 평균대금, 거래량 급증률, 매수/매도 비율
- 원본 데이터 출처·나이·누락 여부
- 점수 구성요소, 총점, 순위
- F1·F2·F3 통과 여부와 제외 사유
- 전략 지문과 설정 ID

필수 키는 `trade_date`, `ticker`, `experiment_id`, `captured_at`이며 UNIQUE로 묶는다.
필수 분석 필드는 `expected_price`, `prev_close`, `gap_pct`, `expected_amount`, `f1_score`,
`f1_rank`, `f1_passed`, `rejection_reason`, `snapshot_hash`다.

### 후보 사후 결과 `candidate_outcomes`

- 실행 가능한 기준 매도호가
- 1·3·5·10·30분 가격과 수익률
- 구간별 MFE·MAE와 발생 시각
- 상승·하락 장벽 중 최초 도달 결과
- VI 발생 및 호가 공백
- 현재 청산정책의 비용 반영 가상손익

각 평가구간은 후보 관측 ID와 horizon으로 UNIQUE하다. `price_source`, `source_ts`,
`bar_complete`, `barrier_order`, `data_complete`, `missing_reason`을 필수 품질 필드로 둔다.

### 진입 비교 `entry_counterfactuals`

- 시가·재검증·최종 호가·실제 체결 시나리오
- 각 시나리오의 실행 가능 수량
- 가상 체결가와 실제 체결가
- 지연·호가 이동·체결 슬리피지 기여도
- 동일 청산정책 적용 손익 차이

### 전략 결과 `strategy_shadow_results`

- 거래 ID, 설정 ID, 전략 지문
- 하드스탑·스텝·트레일 값
- 트리거 시각·가격, 가상 체결가, 청산 사유
- 비용 전·후 손익과 현재 설정 대비 차이
- MFE, MAE, 이익 확보율

`trade_id`, `config_id`를 UNIQUE로 두고 `path_manifest_id`, `decision_exit_price`,
`assumed_fill_price`, 비용 전·후 손익, `discordant_vs_baseline`을 저장한다.

### 실험 등록부 `experiment_registry`

설정을 본 뒤 유리한 기간이나 지표를 고르는 일을 막기 위해 실험 전에 저장한다.

- 실험 ID와 가설
- 기준 설정과 후보 설정
- 시험한 전체 조합 수
- 학습·검증 시작일과 종료 조건
- 1차 성공 지표와 안전성 제한
- 중도 변경·중단 사유
- 최종 승격·폐기 결정

### 설정 등록부 `strategy_configs`

- 설정 JSON과 정규화된 SHA-256
- F1 임계값·점수 가중치·진입 제한·청산 파라미터
- 15:05 강제 트레일, 15:15 F5, 비용·슬리피지 가정
- 코드 지문, 생성 시각, 부모 기준 설정 ID
- `PRIMARY`, `EXPLORATORY`, `ACTIVE`, `RETIRED` 구분

동일 해시의 설정은 재사용하고 값 하나라도 달라지면 새 `config_id`를 만든다.

### 일일 판정 `daily_strategy_reports`

- 거래일, 실험 ID, config ID, 전략 지문
- 네 가지 보고의 JSON 요약과 표본 수
- 필수 필드 완성률·모호 장벽률·불완전 경로 수
- `NO_CHANGE`, `WATCH`, `PROMOTION_CANDIDATE`, `PAUSED` 판정
- 판정 근거, 검토자, 생성 스크립트 버전, 생성 시각

DB 행과 함께 사람이 읽는 Markdown을
`data/reports/strategy/YYYYMMDD.md`에 저장한다. 예정 스크립트는
`scripts/generate_daily_strategy_report.py`이며 F5·정규장 종료 뒤 15:40 KST에 실행한다.
수집 실패 시 성공 보고서를 만들지 않고 `PAUSED_DATA`를 기록한다.

### 가격 경로 목록 `price_path_manifests`

- 거래일, 종목, 거래 ID, 실험 ID
- chunk 파일 경로·SHA-256·압축/비압축 크기·행 수
- 최초·최종 거래소 시각과 수신 시각
- 순번 누락, WS 단절, REST 보강 구간
- 기대 종료 15:15 도달 여부와 `data_complete`
- writer·스키마 버전, 생성·최종화 시각

`trade_date`, `ticker`, `experiment_id`를 UNIQUE로 두며 파일 해시가 달라지면 정정 이력을
남기고 조용히 덮어쓰지 않는다.

## 5. 통계 검증 방법

### 표본 단위

- 실제 청산 설정 비교: 거래일별 한 거래의 paired 차이
- 후보 선택 비교: 거래일을 cluster로 묶은 재표집
- 같은 날 후보 여러 개를 독립 표본으로 세지 않음
- 시간 순서를 섞는 일반 K-fold를 사용하지 않음
- `discordant pair`는 기준과 후보 설정의 결정 청산 시각·가격·사유 중 하나 이상이 실제로
  달라 손익 차이가 발생한 거래일이다. 결과가 같은 거래는 운영 안정성 표본에는 포함하지만
  설정 차이의 유효 정보 수로 세지 않는다.

### 비용과 결측 처리

- 총손익과 초기 비용·슬리피지 가정을 적용한 보수 순손익을 모두 저장한다.
- 호가 또는 장벽 순서가 확인되지 않은 행은 낙관적으로 보간하지 않는다.
- 누락 행은 누락 사유와 비율을 함께 보고한다.
- 설정별로 비교 가능한 동일 거래만 paired 계산에 사용한다.
- 실제 청산 후 경로가 끊긴 거래는 더 느슨한 설정 결과를 만들지 않는다. 설정별 가용률이
  다르면 성능표와 함께 제시하며 완전 사례만의 결과를 전체 성과처럼 표현하지 않는다.
- PAPER 체결 결과와 보수 슬리피지 가정 결과를 별도 열로 제공한다. REAL 전이 가능성은
  보수 결과로만 판단한다.

### 주 가설과 다중 시험 통제

- 첫 확증용 주 가설은 트레일 1.5% 대 2.0% 한 쌍이며 나머지 설정은 고정한다.
- 27개 격자는 탐색용 순위와 다음 가설 생성에만 사용한다.
- 시험 조합을 실험 시작 전에 고정한다.
- 실험 중 새 조합을 추가하면 새 실험 ID와 관측 기간을 시작한다.
- 설정별 평균뿐 아니라 paired bootstrap 신뢰구간을 계산한다.
- 주 가설 하나에는 별도의 27개 중 최고값 선택을 하지 않는다. 탐색 격자를 비교할 때만
  Holm 보정을 적용한다.
- PAPER 승격에는 전체 최소 40거래일뿐 아니라 discordant pair 최소 20건을 요구한다.
  부족하면 기간이 끝나도 결론을 강제하지 않고 계속 수집한다.
- Deflated Sharpe Ratio와 Probability of Backtest Overfitting은 최소 60개 독립 거래일과
  완전한 시험 조합 이력이 쌓인 뒤에만 보조지표로 산출한다. 그 전에는 `N/A`로 표시한다.

참고 연구:

- [The Probability of Backtest Overfitting](https://papers.ssrn.com/sol3/Papers.cfm?abstract_id=2326253)
- [The Deflated Sharpe Ratio](https://papers.ssrn.com/sol3/papers.cfm?abstract_id=2460551)

## 6. 설정 승격 규칙

### 단계 A — 수집 검증 10거래일

목적은 성능 판정이 아니라 계측 검증이다.

- 후보 필수 필드는 `trade_date`, `ticker`, `captured_at`, `experiment_id`,
  `strategy_fingerprint`, `expected_price`, `prev_close`, `gap_pct`, `expected_amount`,
  `f1_score`, `f1_rank`, `f1_passed`, `rejection_reason`, `snapshot_hash`다.
- 결과 필수 필드는 1·3·5·10·30분별 `source_ts`, 가격, 수익률, MFE, MAE,
  `barrier_order`, `data_complete`, `missing_reason`이다.
- 후보 필수 필드의 일별·전체 완성률 95% 이상
- 실제 선택 종목의 15:15 경로 manifest 10일 중 최소 8일 완전, 포함되는 paired 거래는
  경로 완성률 100%
- 시각 역전과 미래 데이터 누출 0건
- 실제 가격 경로로 shadow 결과 재생 가능
- 실제 청산과 현재 설정 shadow 청산의 결정가 일치
- 분봉 `AMBIGUOUS` 비율과 설정별 결측률 산출

이 단계에서는 전략값을 변경하지 않는다.

### 단계 B — 탐색과 주 가설 수집

- 최소 30개 신규 독립 거래일 수집
- 27개 격자는 탐색용으로만 순위 산출
- 확증용 1.5% 대 2.0%는 discordant pair가 최소 20건이 될 때까지 계속 수집
- 후보 설정별 paired 평균·중앙값·신뢰구간 계산
- 특정 하루 제거 민감도 계산
- 시장·갭·유동성 구간별 방향 일관성 확인
- 탐색 결과는 다음 실험의 주 가설 1개를 만드는 데만 사용

### 단계 C — 잠금 검증

탐색에서 선택한 설정과 판정식을 변경하지 않는다. 이 기간은 완전한 미래 검증 구간으로
보존한다. 최소 10거래일과 discordant pair 5건을 모두 충족해야 하며, 10일 안에 5건이
나오지 않으면 기간을 연장한다.

### 단계 D — PAPER 승격

다음을 모두 만족해야 한다.

1. 비용 반영 paired 평균 손익 차이 > 0
2. paired bootstrap 95% 하한 ≥ 0
3. 중앙값 손익 차이 > 0
4. CVaR 10%, 최대 낙폭, 연속손실 악화 없음
5. 상위 수익 1·2건 제거 후에도 개선 방향 유지
6. 전체 최소 40거래일, discordant pair 최소 20건
7. 잠금 검증 최소 10일·discordant pair 5건에서도 평균 차이와 위험 지표 방향 유지
8. 비용·슬리피지 민감도에서 보수 시나리오의 개선 방향 유지
9. 주문 안전성과 데이터 품질 회귀 테스트 통과

한 조건이라도 실패하면 현재값을 유지하거나 새 실험으로 되돌린다. REAL 승격은 이 문서의
범위 밖이며 별도의 REAL 체크리스트와 더 긴 PAPER 증거가 필요하다.

### 실험 중단 규칙

중단 기준은 실험 시작 전에 `experiment_registry`에 고정한다. 초기 기본값은 다음과 같다.

- 주문 중복, 미확인 체결, 손절 감시 중단 등 Critical 안전사건 1건: 신규 진입 중단 및
  안전성 조사
- 단일 거래 보수 순손익 -3.5% 이하: 설정 실험 중단 및 체결·스탑 실패 조사
- 4거래일 연속 손실: 신규 승격 판단 중단 및 위험 검토
- 최근 10거래일 보수 누적손익 -8.0% 이하: 실험 `PAUSED_RISK`
- 후보 필수 필드 완성률 95% 미만 또는 실제 선택 경로 2일 연속 불완전:
  `PAUSED_DATA`; 거래 전략 결과는 통계에 추가하지 않음
- 디스크 소프트 한도 초과나 해시 불일치: 데이터 실험 중단, 주문 로직은 안전한 기존
  설정 유지

중단은 보유 중인 포지션의 규칙을 즉시 바꾸지 않는다. 현재 포지션을 기존 설정으로
종료한 뒤 다음 거래일부터 신규 진입 또는 실험을 멈춘다.

### 승격 후 롤백 규칙

- 승격 후 최소 첫 10 PAPER 거래는 이전 기준 설정을 계속 shadow로 계산한다.
- 후보 설정의 누적 paired 보수 손익 차이가 -2.0%p 이하이거나 최대 낙폭이 기준보다
  2.0%p 이상 악화되면 다음 거래일부터 직전 기준 설정으로 롤백한다.
- 위 실험 중단 기준이 발생해도 같은 방식으로 롤백 검토한다.
- 롤백은 기존 DB 결과를 삭제하지 않고 `ROLLED_BACK` 상태, 사유, 시각, 복귀 config ID를
  등록한다. 재시도는 새 실험 ID와 새 잠금 구간으로 시작한다.

### 0단계 — 계측·기준선 선행조건

- [x] F1 최소 갭 2.5% 설정

- [ ] 현재 설정과 새 전략 지문을 `experiment_registry`에 등록
- [ ] 운영 DB 재기동 후 `trailing_shadow_comparisons` 실제 생성 확인

0단계 항목의 코드·테스트는 병합됐으나(비용 모델, 원자적 완료 증거·공통 F1 스냅샷 선택기,
`experiment_registry`·`strategy_configs`·`price_path_manifests` 스키마·CRUD·기동 시 현재
지문 기준선 등록, 내구 틱 writer·불완전 manifest·분봉 PoC), **라이브·운영 검증이 남았으므로
체크박스는 모두 비워 둔다.** 코드·mock 테스트만으로는 완료로 표시하지 않는다.

- 15:15 durable 경로와 WS 단절·수동 중지·프로세스 종료 불완전 판정: 다음 PAPER 거래일
  1건에서 진입~15:15 manifest `data_complete=1`/`reached_expected_close=1`과 각 중단
  시나리오의 `missing_reason`(WS_LOSS/MANUAL_STOP/PROCESS_SHUTDOWN/RESTART_GAP)을 확인한 뒤
  체크한다. 오늘은 이미 15:15 관측 창 이후이므로 전체 라이브 틱 게이트는 다음 PAPER
  거래일이 필요하다.
- 당일 분봉 API 가용성·호출량·`AMBIGUOUS`: PAPER·09:35 이후·`--with-kis`·≤60 실제 호출로
  수동 확인 후 체크.
- 비용 모델·F1 스냅샷 선택기·기준선 등록: 스키마·등록·상수 반영이 운영 DB에 실제로 남는지는
  다음 정상 재기동 후 읽기 전용 `sqlite_master`/행 조회로 확인한 뒤 체크한다.
- 운영 DB 신규 테이블 생성(`experiment_registry`·`strategy_configs`·`price_path_manifests`·
  `trailing_shadow_comparisons`)은 다음 정상 재기동 후 읽기 전용 조회로 확인한다. 등록 로직·
  스키마는 `tests/test_db_schema_creation.py`로 증명됐고, 운영 DB에는 이미 finalized
  trade-27 shadow가 있어 shadow 테이블 존재는 확인된다.

이 항목을 마치기 전에는 1단계 수집 결과를 승격 통계로 사용하지 않는다. 특히 비용 모델과

## 8. 일일 운영 원칙

1. 금일 결과만으로 설정을 변경하지 않는다.
2. Critical 주문·데이터 오류와 전략 성능 변경을 구분한다.
3. 한 실험 기간에는 한 영역만 변경한다.
4. 변경하지 않은 실험도 시험 횟수에 포함해 기록한다.
5. 좋은 결과뿐 아니라 누락·실패·불리한 결과도 보존한다.
6. 후보 결과 수집과 통계 계산은 주문 크리티컬 패스 밖에서 실행한다.
7. 동시성 1과 1.1초 호출 간격은 유지한다.
8. 강제 트레일 15:05와 F5 15:15는 초기 실험 동안 고정한다.
9. 후보 분봉 수집은 09:35 이후 일 60회 한도, 일일 보고는 15:40에 실행한다.
10. 보고서는 DB `daily_strategy_reports`와
   `data/reports/strategy/YYYYMMDD.md`에 함께 저장한다.
